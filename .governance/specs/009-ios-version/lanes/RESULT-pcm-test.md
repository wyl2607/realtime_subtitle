# PCMConverter 自测加强结果

## 概要
按需求加强了 `ios/Tests/NodeSelftest.swift` 中对 `PCMConverter().append(_:)` 的 CMSampleBuffer 路径测试，新增波形相似度断言（归一化互相关）与左声道单通道测试。

## 变更内容

### 新增测试能力
1. **波形相似度断言**：对每种输入格式，将输出（16kHz s16le）与同频率（440Hz）理想正弦波做归一化互相关，允许 0–40 样本时移（重采样器延迟），要求最大相关性 ≥ 0.95
2. **左声道单通道测试**：48kHz Int16 小端交错，左声道 440Hz、右声道静音，断言：
   - 输出 RMS ≈ 0.3535（0.5/√2，PCMConverter 取左声道不做平均混音），±20%
   - 波形相关性 ≥ 0.95（防声道错位）

### 测试覆盖的输入格式
| 测试用例 | 采样率 | 声道 | 格式 | 字节序 | 布局 |
|---------|--------|------|------|--------|------|
| 44.1kHz立体声Int16大端交错 | 44100 | 2 | Int16 | 大端 | 交错 |
| 48kHz立体声Int16小端交错 | 48000 | 2 | Int16 | 小端 | 交错 |
| 48kHz立体声Float32非交错 | 48000 | 2 | Float32 | 小端 | 非交错 |
| 48kHz左声道440Hz右声道静音Int16小端交错 | 48000 | 2 | Int16 | 小端 | 交错 |

## 变异验证

### 变异操作
临时修改 `ios/Shared/PCMConverter.swift:210` 的小端分支：
```swift
// 原代码
let value: UInt16 = bigEndian ? (UInt16(b0) << 8) | UInt16(b1) : UInt16(b0) | (UInt16(b1) << 8)

// 变异后（小端分支错误使用大端字节序）
let value: UInt16 = bigEndian ? (UInt16(b0) << 8) | UInt16(b1) : (UInt16(b0) << 8) | UInt16(b1)
```

### 变异后测试失败输出
```
FAIL: 48kHz立体声Int16小端交错 归一化 RMS 相差 <20%（预期 0.35355339059327373，实际 0.27596418618439406，相对差 0.21945541033755198）
FAIL: 48kHz立体声Int16小端交错 波形相关性 ≥ 0.95（实际 0.08880293880205313）
FAIL: 48kHz左声道440Hz右声道静音Int16小端交错 归一化 RMS 相差 <20%（预期 0.35355339059327373，实际 0.27596418618439406，相对差 0.21945541033755198）
FAIL: 48kHz左声道440Hz右声道静音Int16小端交错 波形相关性 ≥ 0.95（实际 0.08880293880205313）
```

### 验证结论
- **RMS 断言**：相对差 21.9% > 20% 阈值，成功捕获
- **相关性断言**：相关性跌至 0.089 ≪ 0.95 阈值，强力捕获大小端错位导致的波形破坏
- 大端测试（44.1kHz立体声Int16大端交错）仍通过，确认仅小端分支受影响
- 恢复原代码后所有测试通过：`SELFTEST OK`
