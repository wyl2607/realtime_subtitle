# PCMConverter 混音改造结果

## 改动内容

### 1. `ios/Shared/PCMConverter.swift`
- 新增私有方法 `mixdownToMono(_:)`：将任意声道数的输入 buffer 按帧平均混为单声道（(L+R)/2，N 声道为 N 路之和/N）。
  - 支持 Float32/Int16、交错/非交错布局
  - Int16 按 /32768 归一化到 [-1,1] 再求平均
  - 单声道输入直接转为 Float32 非交错，不做额外混音
- 新增私有方法 `convertToFloat32Mono(_:frames:)`：单声道 buffer 转 Float32 非交错格式
- `convertToWire`：在 AVAudioConverter 转换前先调用 `mixdownToMono`，转换器缓存键改为混音后的格式（单声道、同采样率、Float32）
- 静态方法 `convert(interleavedInt16:sampleRate:channels:)`：同样走混音路径

### 2. `ios/Tests/NodeSelftest.swift`
- `makeTestSampleBuffer` 新增 `rightChannelOnly` 参数
- `runTest` 新增 `rightChannelOnly` 参数
- 原有三组双声道同信号测试预期 RMS 不变（0.5/√2 ≈ 0.3536）
- 「左声道 440Hz、右声道静音」预期 RMS 改为 (0.5/√2)/2 ≈ 0.1768（±20%），相关性 ≥ 0.95
- 新增「右声道 440Hz、左声道静音」48kHz Int16 小端交错用例，预期同上（证明是混音而非挑声道）
- 删除了「只取左声道」的注释，改为说明混音行为

## 实测结果

## 未在真机验证的点

1. **CMSampleBuffer 非交错 Float32/Int16 多声道（>2 声道）输入**：测试仅覆盖 2 声道，理论上支持任意声道数但未实测。
2. **大端模式下的混音精度**：测试用例包含大端交错，但未单独验证大端非交错多声道。
3. **采样率极值（8kHz、192kHz 等）下的重采样 + 混音组合**：测试集中在 44.1k/48k。
4. **真机音频会话中断/路由变更时的连续性**：仅单元测试环境跑通。
5. **长时间运行内存/性能**：混音增加一次逐帧遍历，理论开销可忽略但未做压测。
