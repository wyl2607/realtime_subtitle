# P4 收尾：Windows 主悬浮窗「原位替换」语义（2026-11-04）

接 `p4-result-windows.md` §1.1.1 没做的那半。P3（#116）之后主窗收到的是按 key 的
history 事件（insert / update / delete / move / reset / language），本设计只用这些事件，
**不拆单 QLabel 架构**（拆成每句一个 QLabel 是 L 级风险，见 `p4-baseline.md` §4，仍留作以后）。

## 现状里真正会"跳"的两处

1. **晋升（草稿 → 正式句对）**。本地链路里，一句话成句后先待在 live 行（白色已提交 +
   浅蓝草稿），翻译完成时 translator 按顺序发两个事件：`on_pair`（insert）→ `on_display`
   （live 行去掉这句）。现在主窗处理 insert 时：
   - 新句对按"新 key"淡入：alpha 从 0 起——**这句话本来就在屏幕上**，于是先消失再淡出来；
   - live 行里这句的德语要等下一个 `update_live` 才去掉，insert 那一帧德语出现两遍、
     块高度先涨再缩，上方旧句跟着跳两次。
2. **update（同 key 换译文/原文）**：云端/节点译文覆盖本机译文、失败 ⟳ → 翻译中 → 译文、
   重试成功同 key 再 `add`。P4 W1 已保证它不改可见集合、不淡入，但没有用例钉住。

## 语义

| 编号 | 事件 | 行为 |
|---|---|---|
| R1 | insert，且该行 `src` 出现在当前 `live_committed` 里（= 晋升） | 同一次 `_render` 里：从 `live_committed` 去掉这段原文（首次出现处，接缝处原来有空白才补一个空格，无空格语言自然不补）、清空草稿（原有行为）、**不淡入**（视为已上过屏）。屏幕上这句原地从"live+草稿"变成"正式句对"，只 setText 一次。随后到来的权威 `update_live` 与之相同时走早退，不再重排。 |
| R2 | insert，原文不在 live 行（云端/节点/实时字幕直接上屏的句对、live 已被清掉） | 照旧：新 key 淡入。 |
| R3 | update（dst/src 变化） | 原位换内容：可见 key 集合与顺序不变、不淡入、不触发挤出；正在淡入的 key 继续淡完。 |
| R4 | update 后块的行数不变 | 文档总高度不变 → 底对齐下其它句对 y 不变（"不跳动"）。 |

## 已知限制（不在本次范围）

- **行数变了仍会推动旧句**：单 QLabel + `AlignBottom`，新译文多一行，上面所有句对上移一行
  （顶部裁切）。要彻底不动需要拆成每句独立标签，见 `p4-baseline.md` §4 第 1 条。
- 本地"首次翻译失败"那条路径先发 `dst=""` 的句对（只有原文一行），重试成功后多出译文一行，
  属于上一条。
- R1 的匹配是子串匹配：极短原文（如 "Ja."）可能匹配到 live 行里别处的同样文字。后果只
  持续到紧跟着的权威 `update_live`（同线程按序到达），不丢内容。
- 电视窗 / 影院条 / 历史窗不在本次范围。
- 只在 macOS offscreen 下单测验证，**没有在 Windows 真机上看过观感**。
