# 005 Windows 桌面客户端接算力节点（混合档）

- 状态：已确认（2026-10-11）
- 仓库 / 分支：realtime_subtitle · `feat/macos-native`
- 版本计划：v3.1.0 先发「节点服务端（含 Windows 节点）+ Mac 版 rslite + 003 修复」；本需求随 **v3.2.0** 发布（加功能、老配置照跑 = 次版本位，CLAUDE.md 第 3 节）。
- 前置：001 协议 v2（P1–P8 冻结）、003 的 P5 新版（节点句并集累计覆盖替换）、004 Windows 节点（已装在 yzwdmsnlmm，2026-10-11 真机验收）。
- 与 002（云端识别优先，Groq）的关系：002 的云端节点在客户端看来也是一个节点。本需求把 Windows 客户端的「节点客户端 + 路由 + 替换」做成能直接接上 002 的形状，但不实现 Groq 本身。

## 1. 目标

让 Windows 版 Python/Qt 字幕程序（`main.py`）在**用户打开开关**后，能把识别和翻译交给 tailnet 里更强的节点（yzwdmsnlmm / mini2），本机先出字幕、节点精修替换，节点掉线自动回退本机，体验与 Mac 版 rslite 的混合档一致。

1. **混合档**：本机识别照常先出字幕（首字不慢于纯本机）；同一时段节点的精修结果到达后，按 003 的 P5 规则（本机句被节点句时间并集覆盖 ≥50% 即替换）替换悬浮窗和历史里的本机句对。
2. **自动选节点、自动回退**：按 nodes.json 里的节点探测打分（与 rslite `NodeRouter` 同口径：rtf、rtt、in_use、on_ac、busy），选最好的；节点掉线或忙，字幕不断，回退本机，节点恢复后再切回。
3. **不连自己**：客户端所在机器本身就是节点（例如 yzwdmsnlmm）时，路由跳过它。
4. **节点清单下发**：节点安装脚本（`install_node.sh` / `install_node_windows.sh`）加一个参数，把 nodes.json 条目 + token 同步到指定的 Windows 客户端（经 ssh），客户端只读本机 `%APPDATA%` 下的文件。

## 2. 动机

- 主要场景（用户 2026-10-11 选定）：**弱机器连强节点**。笔记本 / 没独显的 Windows 本机只能跑 small 或 CPU 档（CLAUDE.md 第 2 节：无 N 卡延迟 5–10 秒），而 tailnet 里的 yzwdmsnlmm（RTX 5060，实测 rtf 0.0195，热状态 concat5 WER 0.88%）闲着。
- Mac 版已经证明混合档可行（003 复测：混合档 WER 2.63% < 纯本机 7.89%；Windows 节点热状态 0.88%）。Windows 客户端是用户量更大的那一端，目前完全用不上节点。

## 3. 约束

- **默认关**（用户选定）：更新后老用户行为不变，仍完全本地；⚙️ 面板加「使用算力节点」开关，本机没有 nodes.json 时开关不可用并说明原因。README「不向任何云端发送音频或文本」的承诺不破：节点是用户自己 tailnet 里的机器；开关文案要写清「音频会发到你的节点机器」。
- **只连 Tailscale 地址**：节点 URL 解析结果必须落在 100.64.0.0/10（或 MagicDNS 解析到该网段），否则拒绝连接——与 `_assert_local_ollama` 同一思路，防止配置手滑把系统声音发到外网。
- **token**：只从文件读（`%APPDATA%\realtime_subtitle\tokens\<id>.token`，ACL 仅当前用户），不进命令行、不进日志；日志不写字幕正文（与 001 一致）。
- **协议不改**：用 v2 现有的 `/v1/info` + `/v2/session`；如确需改动，先改 001 的协议文档并保持 rslite 兼容。
- **不破坏现有单机链路**：开关关闭时代码路径与现在等价；第 4 节避坑清单里的已有约束（Ollama num_ctx 统一、`ollama_url()` 钉地址、单实例、torch 在 Qt 前导入等）全部保持。
- **本机识别时间轴**：P5 替换需要本机句带统一样本时钟上的 t0/t1——现在 `on_pair(原文, 译文)` 不带时间，需要从 local agreement 的词时间戳补上（不能用墙钟凑）。
- **翻译**：节点句的译文用节点给的（节点翻译走它自己的 Ollama / Apple）；节点没给译文时用本机 Ollama 补。
- 测试：Windows CI（pytest-windows）必须覆盖新增的纯逻辑；真机验收在一台连节点的 Windows 上做。

## 4. Done criteria

1. **混合档**：Windows 客户端连 yzwdmsnlmm 回放 concat5（或同等德语素材）：最终可见字幕 WER ≤ 纯本机同档 WER，且无「本机句与节点句同时可见」的重复；首字时间不慢于纯本机（±0.2s）。
2. **回退**：回放中途停掉节点 gateway：字幕不断（本机继续出），状态栏显示回到本机；节点恢复后 ≤60s 内重新进入混合档。
3. **不连自己**：在 yzwdmsnlmm 本机打开开关，路由日志显示跳过本机节点（理由可见）。
4. **默认关 & 隐私**：全新安装和老用户更新后开关都是关；开关关时抓包/日志证明没有对 8791 的连接；非 Tailscale 地址的节点配置被拒并给出原因。
5. **下发**：`install_node_windows.sh <节点> --client <windows-ssh 别名>`（参数名在 draft 定）跑完后，客户端机器上出现 nodes.json 条目和 token 文件（ACL 仅当前用户），客户端无需手工配置即可开开关使用。
6. **不退化**：全量 pytest（含 Windows CI）0 failed，ruff 全绿；单机模式真机冒烟（启动/识别/翻译/停止）正常。
7. **文档**：CLAUDE.md 第 4 节补避坑条目、README 补「使用算力节点」一节、`docs/zh/user-guide-template.txt` 同步；`version.py` 进 3.2.0 并写理由注释。

## 5. 明确不做

- 002 的 Groq 云端识别（本需求只保证接口形状能接上）。
- 节点机本机跑字幕时共享节点进程的模型（用户未选此场景）；节点机本机照旧单机运行。
- Tailscale 自动发现节点（用户选定「安装节点时下发」）。
- Windows 客户端手动粘贴 token 的 UI。
- 节点冷启动丢第一段开头约 1 秒音频的问题（TK-008，004 真机已复现，另行处理）。
- macOS 上的 Python 桌面版（A 版）接节点——Mac 用 rslite。
