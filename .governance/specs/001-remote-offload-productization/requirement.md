# 001 外包算力版产品化（小模型本机 + 大模型远程）

- 状态：用户已确认（2026-10-08，含第 1.6 条多节点修改）
- 日期：2026-10-08
- 仓库 / 分支：realtime_subtitle · `feat/macos-native`（当前 3e9fb47）
- 范围：**按多节点架构设计**。这一期真正实现并验收的服务节点和客户端都是 Mac：mini2 当服务节点，MacBook Air 当客户端。Windows 服务节点和 Windows 客户端放到下一期，但协议和路由要能直接接入它们。

## 1. 目标

把已经验证可行的「rslite 远程识别」做成能日常使用的形态：

1. **一键装服务端**：在客户端执行一条命令，就能把服务端装到一台 Mac（例如 mini2）上，并自动配置好访问令牌、开机自启，再把服务器地址回写到客户端配置里。
2. **客户端自动选模式**，用户不用每次决定：
   - **本机准确档**：本机够强时，完全在本机跑准确的大模型，不依赖服务器。
   - **混合档**：本机跑省电小模型、立即出字；服务器上的大模型给出更准的结果后，按音频时间对齐，替换掉对应的那几句。
   - **本机省电档**：本机较弱又连不上服务器时，只跑小模型。
3. **服务端按需加载**：
   - 客户端连上时才加载模型。
   - 客户端断开（或关机、断网）超过一段空闲时间后，自动卸载模型、退出识别进程。
   - 没人用的时候不占内存，也不占 GPU。
4. **服务器那台机器自己当主力机用时**（例如人坐在 mini2 前面），客户端直接用本机的配置和模型，不经网络、不用令牌去「远程调用自己」。
5. **多节点 + 自动路由（用户 2026-10-08 追加）**：服务端/客户端是**角色不是机器**——每台机器都可以既提供算力（节点）又使用算力（客户端）。
   - 可同时存在多个服务节点（mini2 常驻在线做保底；Windows 主机开机后通常更强——N 卡可跑更大/更快模型）。
   - 客户端自动选「当前最合适」的节点：依据节点自报的能力（可跑的识别/翻译模型）、实测延迟、当前负载、是否插电/是否正被本人当主力机使用；最强节点上线时自动迁过去，离线时自动退回次优节点，全都不在则退回本机小模型。
   - 迁移只在**句子边界/停顿处**切换会话，不出现半句重复或丢句。
6. **功耗对比补全**：
   - 补测 A 版（Python Whisper 在本机跑）作为对照。
   - 补测混合档。
   - 统一用 `scripts/bench/power_compare.sh` 的方法测。

## 2. 动机（已有实测）

| | B 本机（系统识别 + 系统翻译） | C mini2（Whisper turbo + qwen 4b） |
|---|---|---|
| 识别错误率（同 67 秒德语） | 7.9% | 2.6% |
| 每段说完到译文出现 | 2.2–4.5 秒 | 5.6–12.3 秒 |
| MacBook Air M2 整机功耗（比空闲多出） | 不到 0.1W | 不到 0.1W |

- **小模型和大模型各有短板**：B 快但不够准，C 准但慢，混合起来可以两头都要。
- **M2 16GB 本机跑 Whisper 会过热**：用户实际遇到过，所以「本机准确档」必须设门槛。
- **服务器空闲时不该常驻模型**：mini2 上还跑着健康同步、iPhone 价格采集等其他服务，16GB 内存要省着用。

## 3. 约束

- **隐私**
  - 音频只走 Tailscale 内网，服务端只监听 Tailscale IP，用 Bearer 令牌鉴权。
  - 服务端不落盘音频，也不保存字幕记录。
  - 客户端界面上必须能看出音频正在离开本机（显示「远程」或「混合」）。
- **本机档位的判断**：按「芯片 + 内存 + 电源」自动判断（用户已确认）。
  - 例如：Pro/Max 芯片或内存 ≥24GB，**并且**插着电源，才进本机准确档。
  - 用电池时，或者是 M2/16GB 这一类机器，只跑省电小模型。
  - 具体阈值在设计阶段（draft）给出，并在 MacBook Air M2 上验证。
- **服务端只同时服务 1 个客户端**（用户已确认）。
- **识别和翻译改成可插拔**：现在服务端的大模型是 Whisper turbo，以后可能换。所以协议和代码都不能把这两个模型写死。
- **兼容和避坑**
  - 不破坏现有 A 版（Python 桌面字幕）在 Windows 和 Mac 上的行为。
  - 遵守 CLAUDE.md 第 4 节和第 7 节的避坑条目。
- **服务端部署位置**：放在内置盘，例如 mini2 的 `~/rs-remote`。mini2 的 `~/projects` 指向一块没挂载的外置盘，不能用。
- **不常驻占内存**：服务端空闲时常驻的部分必须很轻（目标 <50MB），模型只在有会话时才加载。

## 4. Done criteria

1. **一键安装**
   - 在 MacBook Air 上执行一条命令，就能把服务端装到 mini2 并配好开机自启，令牌两端各存一份、权限 600，客户端配置自动写好。
   - 重复执行不出错（幂等）；把同一条命令换一台机器也能装。
2. **按需加载**
   - 没有客户端连接时，mini2 上没有 Whisper 或翻译模型驻留（用进程和内存来验证）。
   - 客户端连上后，在 N 秒内出第一个字（N 在设计阶段定）。
   - 客户端断开后，超过空闲时限，模型和识别进程会被释放。
   - 客户端被强杀、或者断网时，服务端同样能释放。
3. **自动选模式**
   - 在 MacBook Air M2 上：用电池时进省电档或混合档；连上 mini2 时进混合档；mini2 关闭时自动退回省电档，字幕不中断。
   - 在 mini2 本机运行客户端时，走本地，不经网络和令牌。
4. **混合档**
   - 小模型先出字。大模型的结果到达后，按音频时间对齐替换对应的句子，不重复也不丢句。
   - 用同一段 67 秒音频测：「首次出字」不比 B 慢；最终文本的错误率接近 C（≤ C + 1 个百分点）。
5. **多节点路由**：这一期用 mini2 加一个在本机模拟的第二节点来验收。
   - 节点能注册、能被发现。
   - 更强的节点上线后，在下一个停顿处切过去；它下线后，自动退回原来的节点。
   - 切换过程中字幕不中断、不重复。
   - 为什么选这个节点，在日志里看得到。
6. **功耗**：用 `power_compare.sh` 测出空闲、B、C、A、混合五组数据，并写进文档。
7. **质量门**
   - 全量 pytest 和 ruff 通过；Swift 在 release 模式下编译通过。
   - 新的协议行为有测试覆盖。
   - 每个 leaf 任务至少经过 2 轮评审。
8. **文档**
   - CLAUDE.md 第 7 节补上新的避坑条目，README 写清用法。
   - 写明协议 v2 和 v1 的区别。

## 5. 明确不做

- Windows 客户端与 **Windows 服务节点的实现/安装/自启**（下一期；本期只保证协议与路由能接纳它）。
- 多客户端同时连接、排队或负载均衡。
- 公网暴露、TLS 证书、账号体系（只走 Tailscale 内网）。
- 把 qwen 等大语言模型的翻译做成默认路径。服务端翻译默认用系统翻译，需要在 mini2 上下载语言包；qwen 只作为退路。
- 本机准确档具体用哪个引擎（WhisperKit/CoreML 还是 MLX）由设计阶段评估，这一期不承诺上架级打包、签名或公证。
- 改 A 版的 Windows 安装流程。

## 6. 待设计阶段（draft）回答的问题

1. **服务端怎么常驻又不占资源**。候选做法：常驻一个很轻的网关（launchd 守护，不加载模型），有会话时才启动识别子进程，空闲超时就结束这个子进程。另一种是 launchd 的 socket 激活，两种要比较。
2. **混合档怎么按时间对齐**。协议 v2 要给定稿句子带上音频时间（a0/a1）；小模型这一侧可以用 SpeechTranscriber 的 `audioTimeRange`。
3. **怎么判断「我就是服务器那台机器」**：比如本机的 Tailscale IP 是否等于配置里的服务器地址。判断出来以后，本地调用具体走哪条路径。
4. **本机准确档的门槛和引擎选型**。
5. **rslite 只允许开一个实例**：两个实例会互相删掉对方的 tap 聚合设备。
6. **多节点怎么发现、怎么选**
   - 节点从哪里发现：从 Tailscale 设备列表、客户端配置里的节点清单、或节点通过 mDNS 自报，三种里选一种。
   - 节点用什么格式描述自己能跑什么模型。
   - 按什么规则给节点打分。
   - 在句子边界切换节点时，两边怎么交接。
7. **服务端翻译改用系统翻译**：先把 mini2 的德→中语言包下载好（需要用户在 mini2 的界面上点一次）。
